# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Turns a dialogue clip (YouTube URL or local file) into a 1080×1920 vertical video styled like a Chess.com game review: each line of dialogue becomes a "move" with a type (Brilliant/Great/Best/Inaccuracy/Mistake/Blunder), a card with a title and explanation, and an animated eval bar. A person reviews the result, then it goes to TikTok. Everything runs locally and free (yt-dlp, ffmpeg, faster-whisper, Ollama or free-tier Gemini, OpenCV YuNet/SFace, onnxruntime + WeSpeaker, Pillow, Gradio, tiktok-uploader). Optional per-job render settings: pause-on-move (freeze + typewriter), SFX, output format `tiktok|original|landscape`. Besides the automatic LLM analysis the moves can be edited by hand (page «Ходы») or the whole dialogue analysed by hand without any LLM (page «Ручной разбор»).

User-facing strings, LLM prompts, the README and default player names are in **Russian**. Keep new UI text and prompts in Russian.

## Commands

Python 3.12 venv at `.venv/` (3.10–3.12 supported; some deps have no 3.14 wheels). System `ffmpeg` is required, and yt-dlp needs deno or node for YouTube.

```bash
uv venv --python 3.12 .venv && uv pip install -r requirements.txt
.venv/bin/python -m playwright install chromium   # for TikTok upload
.venv/bin/python app.py assets                     # = make_assets.py: icons, SFX, Inter fonts, face/voice ONNX models (fonts + models gitignored)

.venv/bin/python app.py ui                         # Gradio UI on http://127.0.0.1:7860
.venv/bin/python app.py run --url URL --start 1:02 --end 1:45 --white "A" --black "B" --context "…" [--review cli|web|none]
.venv/bin/python app.py run --file clip.mp4 --white A --black B [--no-pause-on-move --no-sfx --sfx-volume 0.5 --format landscape]
.venv/bin/python app.py jobs
.venv/bin/python app.py resume <job>               # run_all on an existing job (skips finished stages)
.venv/bin/python app.py search "query" / models    # YouTube search / list LLM models
.venv/bin/python app.py search --shorts [--max-duration 60 --sort views] "query"   # YouTube Shorts ("@channel words" too)
.venv/bin/python app.py run --search "query" --shorts …                          # pick the source from Shorts
.venv/bin/python app.py describe "source title" [--kind film]                    # the TikTok description describe.py would suggest
.venv/bin/python app.py styles / run|render … --style Неон                        # visual presets
.venv/bin/python app.py analyze <job>              # new LLM pass + render
.venv/bin/python app.py render <job>               # re-render only (moves.json edits or --typing-cps/--read-hold/--sfx-* flags)
.venv/bin/python app.py publish <job> [--caption … --hashtags …]
.venv/bin/python app.py -v …                       # DEBUG logging, full tracebacks
```

The repo has no tests, linter config or git history. Lint ad hoc with `uvx ruff@0.14.0 check --select F,E9,B006,B008 --line-length 130 *.py`. To check layout without a full ffmpeg render, use `renderer.preview_frame(moves, names, avatars, t, output_format)`. It returns a PIL image of the full canvas with the UI at time `t` (video area empty). An existing job such as `jobs/<id>/moves.json` + `avatars/` works as input. To experiment without touching real jobs, copy one into a scratch dir and run with `JOBS_DIR=<dir>`. Note that the user's `.env` overrides defaults (e.g. `VIDEO_MODE`), so pass env overrides explicitly when testing a mode.

## Architecture

Linear pipeline. Each stage is a module, and `pipeline.py` wires them together:

`ingest.py` → `analyzer.transcribe` → `step_faces` (vision + proposed `cast.json`) → `speakers.diarize` (uses the cast-applied vision) → `sounds.detect` → `summary.generate` (LLM) → `analyzer.analyze` (LLM, gets `pipeline.analysis_context`: note + cast + summary + sounds) → avatars (`ingest.prepare_avatars`) → `renderer.py` (uses `reframe.py`, `style.json`) → `review.py` (human approval) → `publisher.py`

`run_all(job, until=...)` can stop after "faces" (the UI's characters dialog) or "summary" (the summary review); the UI's create flow does that when the «Перед разбором показать…» checkbox (prefs `review_before_analysis`) is on, then continues with `flow(jid, stage)` in review.py. Sounds and (in a full run) the summary are best-effort: their failure never fails the video.

Manual path: `pipeline.prepare_manual` (ingest, optional transcribe + speakers, no LLM) → `dialogue.json` edited on «Ручной разбор» (`dialogue.from_transcript` drafts lines and turns existing moves into moments) → `dialogue.build_moves` → `pipeline.save_manual_moves` (+`job.mode = "manual"`) → `step_render`. `moves_edit` validates single-move edits on «Ходы» for either kind of job.

- **Jobs are the unit of state.** `pipeline.Job` is a dataclass persisted as `jobs/<id>/meta.json` (id = `YYYYmmdd-HHMMSS`); it also stores the render settings (`pause_on_move`, `sfx_enabled`, `sfx_volume`, `output_format`; `Job.render_options()`), the source's `source_title`/`source_kind` (video|short|file)/`source_channel`/`work_kind`, and `mode` (`auto` = moves come from the LLM, `manual` = hand-made: `run_all` then never calls the LLM and `recut` shifts the moves and `dialogue.json` instead of deleting them). `Job.load` ignores unknown keys and new fields have defaults, so old jobs keep loading. Stage outputs sit next to it: `clip.mp4`, `transcript.json`, `vision.json` + `faces/person<N>.png`, `speakers.json`, `moves.json`, `avatars/{white,black}.png`, `final.mp4`, plus `inputs/` for uploaded avatars, `dialogue.json` (manual analysis), `moves.orig.json` (the moves before the first hand edit, made by `pipeline.save_manual_moves`) and `preview/` (placeholder avatars for card previews). `run_all` is resumable: it skips any stage whose output file exists, so you rerun a stage by deleting its file. Avatars are always regenerated. `status` tracks progress, and failures set `status="failed"` + `error`. Face/speaker analysis never fails the pipeline: errors are logged and the stage degrades (no hints, placeholder avatars, centre crop).
- **Source cache and downloads.** `ingest.inspect_source` classifies the input first (URL, video file, `.txt` with a link; images, audio-only, text without a link, folders, missing paths raise `SourceError` with Russian text) — `create_job` calls it, so nothing is created for a wrong input, and files uploaded through the UI are hard-linked into the cache (`keep_upload`). `ingest.fetch_source` keeps downloads in `config.SOURCES_DIR` (`jobs/_sources/<video_key>/`; `list_jobs` ignores it because it has no `meta.json`) as `part_<a>_<b>.*` (the selected fragment ± `SECTION_MARGIN`, `--download-sections --force-keyframes-at-cuts`) and reuses any cached `full.*` / covering part. **It never falls back to a full download on its own**: a failed fragment raises `PartialUnavailable` (after one retry for expired / 403 / network) unless `job.allow_full_download` (set only by the person: the UI dialog `ui_download` or the CLI prompt / `--allow-full-download`); no fragment in a video longer than `FULL_DOWNLOAD_ASK` raises `NeedsRange`. yt-dlp failures become `DownloadError(kind, title, hint)` via `ingest.classify` (`DL_KINDS`: auth, age, members, private, unavailable, geo, drm, live, rate, forbidden, expired, outdated, network, unsupported); `remote_info` raises the final kinds before any download and also gives the duration (ffprobe for direct files) used to check the timecodes. Progress: `ingest(..., progress)` reports «Проверка источника» → «Сведения о ролике» → «Скачивание фрагмента … N%» (yt-dlp `[download] N%` or ffmpeg `time=`) → «Обрезка фрагмента N%» (`-progress pipe:1`). Cookies only come from the person's explicit choice (`ingest.set_cookies` writes the browser name / file path to `.env`, never values; `_redact` hides cookie-ish text in logs). `YTDLP_BIN` selects another yt-dlp; `update_ytdlp` upgrades it. The exact cut is always local (`normalize(src, dst, start, duration)`: `-ss` before `-i` with re-encoding, then `-t`). `pipeline.recut()` changes a job's in/out points and deletes everything in `CLIP_DERIVED`, so the next `run_all` rebuilds from the cache.
- **CLI and web UI share the same code path.** `app.py` (argparse) and `review.build_ui()` (Gradio) both call `pipeline.*` and `review.approve_and_publish/reject`. Logic goes in `pipeline`/modules, not in UI handlers. Job settings (`OPTION_FIELDS` = the fields of `renderer.RenderOptions`, plus `llm_provider`/`llm_model`) are set through `Job.set_options(**kw)`, where `None` means "keep". Adding a render option means adding it to `RenderOptions`, `Job`, `prefs.defaults()`, the UI `settings` list and the CLI flags.
- **Logging is user-facing.** `console.setup()` installs `HumanFormatter`. Log messages are short Russian sentences: `▶` marks a stage header and `✓` a result (both emitted by `pipeline` steps), technical detail goes to `log.debug`. Errors reach people only through `errors.explain(e)`, which matches regex rules against the exception text and returns a Russian title plus a hint; add a rule there for new failure modes instead of printing tracebacks. Web UI actions run in `review.LiveRun` (worker thread plus a `console.RunLog` handler filtered by thread id), and the Gradio generator `live()` streams status and journal every 0.5 s, returning dicts keyed by component.
- **`config.py` is the single source of settings.** It loads `.env` from the project root at import, and every tunable is an env var (see `.env.example`). It also holds `MOVE_TYPES` (glyph, color, Russian label), `THEME` colors and the `LAYOUT` dataclass. `LAYOUT` derives all vertical positions: card → players bar → eval bar → video. Change geometry in `Layout` rather than hardcoding pixels in the renderer.

- **Characters (cast.py).** vision.py keeps every notable face (≤ `MAX_PERSONS`, crops `faces/person<N>.png` by raw rank). `cast.json` maps raw ranks to name / side / removed / merged_into; the project registry `config.CAST_DIR` (`jobs/_cast/`) keeps confirmed characters with a running-mean SFace embedding. `pipeline.load_vision` returns `cast.apply(raw, cast)`: merges, drops removed faces, renumbers so white = person 0, black = person 1 (`va.crops` maps new numbers back to crop files; `vision.person_crop(..., va)` uses it). Unconfirmed casts only contribute confident registry matches (`JobCast.trusted`, `SURE`); a guessed side is trusted only when it came from the job's player name or the names are still the defaults. `raw_vision` is what the dialog shows.
- **Sounds (sounds.py).** YAMNet ONNX (`assets/models/yamnet.onnx` + class map, downloaded by `make_assets.ensure_sound_model`, 16 MB) gives 0.48 s frames → events per `KINDS` (class-name prefixes, thresholds, `certain_at`); prosody events compare each segment with the same voice label's robust z-score. An event is tied to a side only when the speaker hint is confident. `edited` / `source="user"` events survive `merge_redetected` and `recut` (shifted); `include` drives the video tags (`render_tags`, at most `TAG_MAX` s) and `context_text`.
- **Summary (summary.py).** The LLM must cite segment ids (`evidence`); an item is reliable only when it is marked certain *and* backed by existing ids (characters also need a confirmed / heard name). Edited sections (`edited[sec]`) survive `merge`. The editor's text form: one item per line, "? " = guess, "Имя — …", "0:12 — …".
- **AI failures.** `step_analyze` / `step_summary` tag exceptions with `e.ai_stage`; `errors.is_ai` / `errors.ai_kind` classify (temporary, limit, auth, model, offline, output) and `llm.alternatives` lists usable models. `live(..., ai_op={...})` opens the `ui_ai` dialog on such a failure; `on_ai_retry` in review.py maps the stored op ("run", "flow", "summary", "reanalyze", "refine") back to its action, optionally after switching job + prefs to another model. Completed stages are files, so a retry only repeats the failed request.
- **Style (style.py, renderer.Composer).** Every drawing function takes a `VideoStyle`; `styled_layout(st)` derives the `Layout`. `Composer` (geometry, UI, schedule, reframe plan, `VideoOverlay` for subtitles and sound tags) produces output frame k for both `render_video` and the style editor's preview, so they match (verified: mean pixel diff ≈ 1.3 after x264). With the default style the output is pixel-identical to the pre-style renderer. New animated properties go into `FrameState.key()`, new overlay content into `VideoOverlay.key()`. Fonts must cover Cyrillic and render without complex shaping (Playfair Display was dropped: Pillow without raqm breaks its «й»/«л»).
- **Description (caption).** `describe.suggest(title, kind, channel, meta)` builds "Разбор диалога[ из фильма]: <work> #шахматы #разбор #…" by rules (no LLM): `clean_title` strips emoji/hashtags/quality noise/the channel, `parse_title` finds the work and scene, `detect_kind` scores evidence from the title and yt-dlp metadata (`ingest.source_meta`, cached `info.json`) and only accepts a clear winner. Never add a fact that is not in the title or metadata; `refine_with_llm` discards an LLM answer whose work is not a substring of the title. `Job.caption_generated` is the last automatic text and `caption_edited` = the caption differs from it: `pipeline.refresh_caption` replaces the caption only when it was not edited, otherwise the UI offers the new text next to it («Заменить предложением»).

### analyzer.py: key design decisions
- faster-whisper runs with `word_timestamps`, and segments are re-split at sentence ends (`_split_on_sentences`).
- **The LLM never produces timestamps.** It gets numbered segments and returns `first_segment`/`last_segment` indices (`LLMMove`), and `llm_to_moves` maps those back to exact whisper times. The final model is `Move`, the `moves.json` format documented in the README.
- Two Pydantic schemas share `_MoveFields`, whose `mode="before"` validators are deliberately lenient. They accept Russian aliases for move types and speakers, numbers inside strings, and clamp eval to ±10. `parse_moves` handles user-edited JSON through the same path.
- `analyze()` loop: JSON-schema-constrained request → validate → `check_llm_moves` (move count from `target_moves`, ≥80% segment coverage, placeholder text). Any problems are fed back to the model as a follow-up message, up to `LLM_MAX_RETRIES`. If none pass, the best attempt is used.
- Post-processing: `sanitize_moves` (sort, clamp to clip duration, remove overlaps, **rewrite the `move_number` prefix "N "**) and then `shape_evals`. `shape_evals` overrides the LLM's eval numbers: the sign has to match the move type, and each swing is scaled by `EVAL_GAIN` with a per-type minimum (`EVAL_MIN_SWING`).
- Speaker hints (`speakers.SpeakerHints`, from `speakers.json`) add `| голос A (97%)` tags to every prompt line. Labels are anonymous unless user avatars match a face (`hints.sides`). `check_speakers` feeds contradictions (a move mixing labels, or a speaker that disagrees with the label→side mapping the LLM itself chose) back into the retry loop. After the retries, `fix_speakers` flips a move's speaker only when voice and face *both* confidently disagree with it. `analyzer` must not import `speakers` (speakers imports analyzer).
- LLM providers live in `llm.py` (`analyzer.get_provider/list_models/default_model` are aliases). `llm.SPECS` is the registry: pollinations/github/groq/openrouter/mistral all go through `OpenAICompatProvider` (plain `requests`; JSON mode and `extra_body` fields are dropped automatically if a model rejects them; `<think>` blocks are stripped), while Ollama and Gemini have their own classes. Each provider is picked per job; `LLM_PROVIDER` is only the default, and `config.LLM_PROVIDERS` must list the same ids. Transient errors (5xx/429/402, honouring `Retry-After`/"Retry after Ns") are retried with `TRANSIENT_WAITS` backoff. Provider errors are raised as `llm.LLMError(title, hint)` with Russian text, which `errors.explain` passes through. Keys are read only from the environment/`.env` (`Spec.key_env`); `llm.save_key` validates against the provider API before writing `config.ENV_FILE` (mode 600). Tests must set `ENV_FILE` to a scratch file.
- The model also returns `effect` and `strength` (−3..+3) per move, and `llm_json_schema` orders the fields so it reasons before classifying. `check_llm_moves` requires `move_type` to match `strength` (`TYPE_STRENGTH`), limits Brilliant moves and flags a monotone type distribution. A missing `strength` (`None`) skips the check.
- The system prompt bans clichés and `check_llm_moves` enforces it (`CLICHES` regex → a retry issue). Small models copy prompt examples verbatim, so style examples must come from an unrelated invented scene, never from a real test clip.

### vision.py / speakers.py
- `vision.analyze_video` makes **one decode pass**. Shot cuts come from the mean of the most-changed 40% of thumbnail pixels vs. the recent median. YuNet runs at `VISION_FPS`, faces are linked into per-shot tracks, and tracks are clustered into persons by SFace embeddings (co-occurring tracks can never merge). Persons are ranked by screen presence: person 0/1 are the players. Mouth activity is measured on landmark-aligned faces. All coordinates are normalized 0..1. Cached in `vision.json`, keyed by clip size/mtime + FPS settings; bump `VERSION` when the format or algorithm changes.
- `speakers.diarize`: WeSpeaker voice embeddings (numpy Kaldi fbank → onnxruntime) are clustered by average linkage. The fallback is MFCC/F0 at reduced trust. The video vote uses an absolute mouth-activity threshold (`TALK_LEVEL`): a visible face with a still mouth points to the *other* person. Both channels are fused in log-odds after matching voice clusters to faces; audio is dropped if they disagree. Label A = person 0.

### renderer.py / reframe.py
- **Python is the compositor**: ffmpeg decodes source frames (raw RGB), numpy places the reframed video box (`reframe.Framer`) and the Pillow UI on the canvas, and frames are piped to an ffmpeg/x264 encoder. `geometry()` defines canvas, UI position and video box per output format (landscape = side panel `LANDSCAPE_PANEL_W`). All UI drawing takes a `config.Layout` (with `width`) instead of global sizes.
- `build_schedule` maps every output frame → (source frame, `FrameState`) and lists playback `runs` and SFX events. In pause mode the source frame stops at each move's end (+`PAUSE_TAIL`) for `pause_duration(chars, opts)` (= card fade + chars / `typing_cps` + `read_hold`) while the card pops in and the body is typed (`FrameState.reveal`). Before the first pause an intro card (`idx=-1`) is shown. Audio is built in numpy from the same `runs` (silence during pauses, 15 ms declick) plus SFX, then soft-limited. That is why A/V sync is exact; keep audio and video driven by the schedule.
- Identical consecutive frames reuse the previous canvas: the video tile is keyed by (source frame, plan row) and the UI by `FrameState.key()`. Any new animated property must go into `key()`.
- `reframe.plan` is per source frame, so freeze frames automatically keep their crop. `VIDEO_MODE=smart` works per shot: static / follow / speaker-focus (eased pans) / FIT over blurred background, and vertical sources are always FIT. Legacy `fill|crop|fit` keep the old static behaviour.
- Card height is fitted once per video (`fit_card_height`, between `card_min_h` and `card_max_h`), so every card has the same height.

### review.py (web UI) + design.py
Pages: create | moves | manual | sounds (`ui_sounds`) | style (`ui_style`); dialogs `ui_cast`, `ui_ai` and the search picker are fixed overlays built before the shell row (their components must exist before `outs`). The trim editor (`ui_trim` HTML + `window.cdmTrim` in design.HEAD: YouTube IFrame API before download, `<video>` from the source cache / a hard link of a local file after) writes into `#cut-start` / `#cut-end`.

Look and feel: `design.py` holds the tokens (`TOKENS` → CSS variables `--cdm-*`), the Gradio theme (light and dark get identical values: the UI is dark-only), generated line icons (`design.icon(name, tone)` writes `assets/ui/icons/*.svg`) and `HEAD`, two page scripts: (1) Ctrl+K / Esc, the mobile hamburger, active-section highlighting, status/job badges; (2) `window.cdm` for the editor pages (seek/play-range on `#moves-player`/`#manual-player`, playhead, clicks on `.cdm-tl-seg`/`.cdm-card` that seek and select the matching list item via `data-list`/`data-value`, transport buttons, keys Space/←/→/I/O/N, URL hash ↔ page). Component styles are in `assets/ui/style.css`.

Layout: glass `#site-header`, then `#shell` (`#sidebar` | `gr.Tabs#pages` with its tab header hidden). The sidebar has `#pages-nav` (Radio: create | moves | manual; `#moves`/`#manual` hashes deep-link), section anchors and past jobs `#jobs-nav` (labels "title · when · status"). The create tab is `#create-grid` (`#content` | `#aside` with preview, JSON and publication). `ui_moves.build(shell)` and `ui_manual.build(shell)` build the other tabs; `shell` (a SimpleNamespace made in `build_ui`) gives them `job_id`, the dock components, `live()`, `need_job` and `jobs_nav`/`nav(jid)` to refresh the sidebar after a status change. Each page returns `load(jid)` + its `outputs`, and `on_page`/`on_select` call the visible page's `load`. Progress lives in the bottom `#dock` (`status` Markdown + `bar` HTML, «Подробности» toggles `#dock-details` with `journal` and `tech`). The dock is created with `render=False` before the pages and rendered last. Gradio 6 has no modal: the search picker is `gr.Column(visible=False, elem_id="search-modal")` styled as an overlay; `open_search` is a generator (first the dialog with «ищу…», then results) and `search.py` caches each query for `CACHE_TTL`, so filters and sorting are local.

Editor pages: the list rows (`#moves-list`, `#lines-list`, `#moments-list`, `#jobs-nav`) are Radios whose labels are fields joined by `ui_parts.SEP`; the page script never rewrites Svelte-owned nodes but adds a sibling `.cdm-rich` copy (`window.cdmRich`) rebuilt when the label text changes. Edits autosave when another item is picked; an invalid edit blocks the switch (the radio value is put back). Destructive buttons need a second click within 6 s (a `confirm` State). `moves_edit.py` and `dialogue.py` hold all the logic and validation (Russian messages); the UI modules only map form fields.

Gradio 6 gotchas met here: `show_progress="hidden"` everywhere; `ui.load(on_page_load)` re-reads prefs and jobs on every page open (build-time values are frozen at server start). Return one entry per component: `{**base, comp: value}` silently drops an earlier `comp: gr.update(visible=True)` (use `gr.update(value=…, visible=…)`). Components with `visible=False` are not in the DOM at all. A click on a Dropdown option fires `.input` twice (and `.select` misses keyboard picks): use `.change` when no handler sets that dropdown. `js=` on an event with `fn=None` returns values for the outputs; with `fn` it rewrites the inputs (that is how the player time reaches the server). Handlers that take `gr.SelectData` must set it in `__annotations__` at runtime. `buttons=[]` removes the extra corner buttons of `Slider`/`Gallery`/`Image`/`Video`. CSS: row children get `flex-wrap: wrap` (a column then wraps into two: force `nowrap`), Radio `.wrap` in column direction needs `flex-wrap: nowrap` too or rows grow to max-content; neighbouring form fields of a row are wrapped in one `.form` and blocks carry `auto-margin`; a hidden status tracker (`.wrap.hide`) is the first child of rows (never style by `:first-child`). Every custom selector is prefixed with `.gradio-container… .contain`, so `body`/`html` selectors never match. `backdrop-filter` (the header) and `transform` (the mobile sidebar) trap `position: fixed` children. In Gradio 6, `theme`/`css`/`head` go to `launch()`. Inspect the real DOM with Playwright before styling a component. When testing the UI, point `PREFS_FILE`, `JOBS_DIR`, `ENV_FILE`, `CAST_DIR`, `PRESETS_FILE` and `SOURCES_DIR` at scratch paths; download failures can be simulated with `YTDLP_BIN=<script.py>` (a wrapper that prints a yt-dlp error, else calls the real one) and a local `python -m http.server` as the source. `review.harden(ui, status)` wraps every handler after the build: exceptions become a status message / toast, an empty dict becomes `gr.skip()` per output (Gradio 6 would read `{}` as one value and fail), keys that are not outputs are dropped. Page `finish` views run only after success (a failure keeps the form). Bind controls that a handler also sets programmatically to `.input` / `.release` (not `.change`), or a preset that sets 40 controls fires 40 redraws.

### publisher.py
tiktok-uploader drives a Playwright browser using Netscape-format `cookies.txt` (gitignored, as are all `*cookies*.txt`). TikTok has no official posting API, so uploads break when its layout changes (`pip install -U tiktok-uploader`), and cookies expire.

## Troubleshooting (from README)
- YouTube "Sign in to confirm you're not a bot": set `YTDLP_COOKIES_FROM_BROWSER=firefox` (or `YTDLP_COOKIES=path`).
- If section download gets a 403, `ingest` downloads the full video and cuts it with ffmpeg. Clips are normalized to CFR H.264.
- `qwen2.5-coder` (the default `OLLAMA_MODEL`) writes noticeably worse Russian and confuses speakers more often than `qwen2.5:7b`+.
